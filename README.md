# StackPilot 开发项目工作台

面向独立维护运营部工具的开发者。台账保存在你的电脑上，工具可以继续在同事各自的电脑上使用。每个程序有独立档案，可关联使用说明、发布版本、同事反馈、项目目录及运行监控。首次启动会生成 12 个示例程序和约两周的运行记录，另有 14 条示例版本和 5 条示例反馈。

## 启动

需要 Node.js 22.13 或更高版本。在项目目录执行以下命令。

```sh
npm ci
npm run dev
```

在浏览器打开 [本机工作台](http://127.0.0.1:5173)。正式使用时可先执行 `npm run build`，再执行 `npm start`。两种启动方式默认使用同一份数据库。端口可通过环境变量 `PORT` 配置。

## 工具箱与独立电脑项目

“钊叔工具箱”及其 7 个入口取自正式标签 v0.4.24 的应用导航。可按丹姐、三公、双姐、谭、董卓定位对应模块。公开档案只记录仓库中可核实的信息，部署位置和运行状态在本机接入后更新。[工具箱说明](https://github.com/xyq20/ZSZ-Tools/blob/v0.4.24/README.md) · [正式版本导航](https://github.com/xyq20/ZSZ-Tools/blob/v0.4.24/app/index.html)

工具箱的发布记录与 GitHub 官方 Releases 对应。初始化保存了 2026 年 11 月 19 日发布的 v0.4.24。手动刷新会读取已登记公开仓库的最新正式版，同一版本只保留一条。子项目沿用宿主的发布入口和版本。网络不可用时仍可查阅已保存的发布记录。[v0.4.24 正式发布](https://github.com/xyq20/ZSZ-Tools/releases/tag/v0.4.24)

“批量图片处理”演示独立电脑项目。可以登记设备别名、远控入口与连接说明。支持 HTTP(S)、RustDesk 和 AnyDesk 数字设备链接，认证在相应客户端中完成。机器别名和说明可单独使用。

## 动态工作间

从左侧“动态工作间”进入 19 席座位图。点工位后可以填写姓名、绑定多个项目，配置会保存到当前工作台的 SQLite。旧座位图的本机网页入口会转到这里，同源浏览器中曾填写的姓名会补到尚未填写的工位。

人物有独立身份，可设置性别、20 款原创造型、主题色和生活偏好。填写姓名或关联项目后人物入场，“换座”会一起移动人物与项目。在座时使用与工位方向匹配的全身坐姿，手掌与键盘对齐。默认开启“自动生活”，以工作为主，偶尔短休；手动选择“工作”会保持专注 10 分钟。人物可沿走道接水、到门外上洗手间、回座工作、摸鱼、伸懒腰，也会和同事碰面聊天。点人物可在右侧安排动作；点饮水机可让选中的角色去接水。生活动作是场景演绎。手动动作在打开的工作间之间同步，暂离与聊天会自然结束。

工位屏幕和告警提示读取实际的工作台记录。项目数据变化会推送到打开的工作间，人物离座时也可点原工位查看项目；子项目沿用宿主的发布记录。示例工作区预置六个项目绑定，姓名留空。可用场景右上角的导出按钮保存当前画面。

手机上发起动作后会自动返回现场。点“查看档案”回到所选工位。放大时可左右滑动，或用“定位工位”跳到另一席；按 Esc 或点“收起”可退出放大。

## 找回 Codex 会话

工作首页有三个入口。“继续上次开发”提供项目关联和“本机最近”两种查找方式。关联列表优先显示在当前浏览器打开、复制过链接或发起过远控的会话。“查找部门工具”可以按工具名、使用方、已绑定工位的同事或电脑搜索，点击结果进入项目档案。“处理待跟进问题”集中显示未解决反馈和告警，点击即可打开对应记录。手机上可在这三个入口之间切换。

全局搜索支持项目名、电脑别名和已关联的会话标题。“Codex 会话”页还可以按工作目录或 ID 检索当前电脑的会话索引。

本机会话可直接打开。其他电脑的关联会显示设备名，可复制会话链接，在那台电脑的 Codex 中打开；为开发电脑登记远控入口后，可从档案或会话页进入远控。同一台开发电脑的多个项目可以共用该入口。关联关系保存在工作台 SQLite 中。[Codex 官方深链说明](https://learn.chatgpt.com/docs/reference/commands#deep-links)

### 从另一台电脑带回会话关联

1. 在工作台的会话页下载 `StackPilot-Chat-Link.py`。从单个项目下载时，助手只携带该项目的编号和名称；从全部项目下载时可以在助手中切换项目。
2. 把这个单文件带到实际保存 Codex 会话的电脑。用该电脑的 Python 3 运行，macOS/Linux 可用 `python3 StackPilot-Chat-Link.py`，Windows 可用 `py -3 StackPilot-Chat-Link.py`。已关联 Python 的系统也可以双击文件。助手会在本机临时端口打开浏览器，无需安装额外软件包。
3. 填写便于识别的电脑名，选择项目，按标题、目录或会话 ID 搜索。勾选会话后可切换项目继续选择，然后点击“下载关联清单”。单份清单最多 200 条关联。
4. 把 `StackPilot-Chat-Links.json` 带回工作台，在会话页导入。JSON 包含来源电脑以及选中的项目编号、会话编号、标题和工作目录。原聊天保存在来源电脑上。
5. 点击助手页面的“结束助手”可停止临时服务。再次使用时重新运行 Python 文件即可。

助手使用当前用户的 `CODEX_HOME`，默认读取 `~/.codex`。它以只读方式从状态数据库查询会话元数据，也支持 `session_index.jsonl` 备用索引。后者若未记录工作目录，该字段保持空白。

## 工具管理演示

打开“表格清洗工具”的程序档案，阅读使用说明，并打开 1.2.0 版本附带的离线 HTML 工具。载入样例后执行清洗，可以复制结果或下载 TSV 文件。该样例也可保存为单个 HTML 文件在本机浏览器打开。

每个程序可以维护以下信息。

- **使用资料**包括使用团队、运行方式、使用说明与现有工作台入口。目录支持使用中和已归档两种状态，归档后保留历史资料。
- **版本发布**记录版本号和更新说明，同一程序内的版本号唯一。可附带 HTTP、HTTPS 资源地址或随工作台提供的示例附件。下载地址留空时只保存发布记录。
- **同事反馈**由维护者录入，记录相关版本、反馈人、问题和详情，可由待处理转为跟进中或已解决。
- **运行监控**可按需接入。管理版本和反馈只需登记资料。对本地集中运行的关键自动化，可额外接入心跳与任务结果。

## 可选：接入本机自动化任务

1. 在工具台账登记项目，填写使用团队和工具入口，选择“定时任务”。项目路径可在工具档案的“编辑基本信息”中补充。
2. 在工具档案打开“查看接入与运行详情”，使用“重置接入密钥”生成并保存程序专属密钥。复制程序 ID，将密钥放在该程序的环境变量中。再次重置后需要同步更新程序配置。
3. 在程序启动和定时循环中上报心跳。上报间隔应短于登记时设置的超时时间，例如每分钟上报一次、15 分钟未上报时标记离线。
4. 每当一项任务结束时，上报任务名称、结果和耗时。一次具体执行使用一个唯一的 `eventId`，重试同一条上报时复用它。

工作台通过程序主动上报判断状态。登记目录用于关联项目位置，程序继续由原有方式启动。

### 心跳

以下示例从环境变量 `STACKPILOT_APP_ID` 和 `STACKPILOT_TOKEN` 读取接入信息。每个程序只能用自己的密钥上报。

```sh
curl --fail-with-body -X POST \
  "http://127.0.0.1:5173/api/ingest/${STACKPILOT_APP_ID}/heartbeat" \
  -H "Authorization: Bearer ${STACKPILOT_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"status":"healthy"}'
```

可用状态为 `healthy` 和 `warning`。异常心跳可附带 `message`。进入异常状态会产生告警，恢复健康后会自动解决该心跳告警。超时离线告警在下次收到心跳时自动解决。

### 任务结果

```sh
curl --fail-with-body -X POST \
  "http://127.0.0.1:5173/api/ingest/${STACKPILOT_APP_ID}/runs" \
  -H "Authorization: Bearer ${STACKPILOT_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"eventId":"order-import-20261119-001","title":"订单导入","status":"success","duration":1280,"message":"已导入 24 笔订单"}'
```

`duration` 使用毫秒，`status` 支持 `success` 和 `failed`。失败结果会产生可跟进的告警。同一程序重复上报相同 `eventId` 时，接口返回原记录的 ID 和 `duplicate: true`。

## 数据与测试

SQLite 数据默认保存在 `data/workspace.sqlite`。仓库包含已提交的工作区快照，新电脑克隆后直接运行即可载入其中的项目、工位和历史记录。工作台展示最近 15 天的运行记录。

要把新的数据改动带到另一台电脑，先停止源电脑上的工作台，让 SQLite 将事务日志写回主库，再检查并提交 `data/workspace.sqlite`。两台电脑轮流修改这份快照，换电脑开始工作前先拉取最新提交。运行期间的 `-wal` 和 `-shm` 文件由 SQLite 管理。需要完整本地备份时，停止服务后复制整个数据目录。

切换到全新的真实工作区时，用独立目录启动并关闭示例初始化，已有演示数据仍可单独保留。

```sh
STACKPILOT_DATA=./data/live STACKPILOT_DEMO=0 npm start
```

服务仅监听本机回环地址。运行 `npm test` 会启动临时服务和独立数据库，验证程序接入、告警、重复上报、工具版本管理、反馈处理、旧数据库升级以及重启恢复。
